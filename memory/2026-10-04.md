# 2026-10-04

## Project: tiny-moe (Mixture-of-Experts LM from scratch, CPU-first)

User's learning project. Goals in order: (1) train tiny MoE decoder LM 10-50M
params in PyTorch, (2) CPU inference with quantization. They want staged
delivery with design rationale, and CPU pain points flagged BEFORE code.

User hardware: laptop 16GB RAM, AMD PRO 5650U (Zen3, 6c/12t, AVX2, no
bf16/AMX), no dGPU. Free Colab is an option.

### Stages agreed
1. MoE layer (router, top-2, aux loss) ✅ done today
2. Transformer (RoPE, GQA, blocks, full model)
3. Training loop (tokenizer, data, AMP-with-fallback, logging, ckpt)
4. Training run (TinyStories)
5. Quantization (own GGUF writer + numpy int8/int4)
6. CPU inference script

### Stage-1 state
- Code: `tiny-moe/tinymoe/moe.py`, tests: `tiny-moe/tests/test_moe.py`
- Design: SwiGLU experts (3 mats), softmax router no-bias, gates renormalized
  over top-k, Switch aux loss L=E*Σ f_i*P_i (hard counts no-grad + soft P),
  sorted-dispatch grouped GEMM loop over experts, index_add_ recombination,
  no capacity factor.
- Key finding documented: top-k aux loss ceiling is **E/k** (=4 for E=8,k=2),
  not E — useful signal range is [1.0, E/k]. First test version wrongly
  asserted >4 for collapse; fixed to 3.5<aux<=4.01.
- Verified: dispatch == naive reference (err 3e-10), aux=1.0 at init,
  collapse aux=4.0, grads flow, bench on sandbox (3 vCPU Xeon):
  MoE layer fwd+bwd ~25k tok/s @1024 tok, ~35k tok/s @8192 tok.

### Flags given to user (CPU pain points)
- CPU training slowest stage: plan ~10-20M model + TinyStories subset, or Colab
  T4 for real run. fp32 on CPU (Zen3 lacks bf16/VNNI), AMP only when CUDA.
- GGUF compat trap: self-written GGUF only runs in llama.cpp if arch string,
  tensor names, quant formats match exactly. Plan: numpy int8/int4 + own
  inference first (guaranteed), GGUF writer second (learning).
- Param budget sketch (stage 2 to finalize): d=512, 6 layers, GQA 8q/2kv
  head64, ffn_hidden=384/expert, vocab 4096 tied emb → ~34M total, ~13M
  active/token.

### Stage-2 state (same day, later)
- Built: `rope.py` (RoPE + "none"/"linear"(PI)/"ntk" scaling hook, extendable
  cache), `attention.py` (GQA 8q/2kv, incremental KV cache, chunked-append
  mask), `blocks.py` (RMSNorm pre-norm block, DenseFFN baseline wrapper),
  `model.py` (ModelConfig, TinyMoE with tied emb, gradient-checkpoint flag,
  generate() prefill+decode, num_params active/total, kv_cache_bytes).
- Tests all pass: causality err 0.0, incremental cache == full forward 2.4e-7,
  rope angle checks, dense FFN param parity, param audit 34.4M total / 13.1M
  active (38%), KV cache @8k 50MB fp32 / 13MB int8.
- Bench: full model fwd+bwd @2k batch1 = 1876 ms/step -> 1092 tok/s on sandbox
  (3 vCPU). Laptop extrapolation ~550-750 tok/s -> overnight ~20-25M tokens.
- User confirmed: no checkpoint existed; base run = laptop @2k, long-ctx = Colab
  T4. Stage 3 next: tokenizer (BPE), TinyStories packed w/ EOS, train loop.
- Planned for stage 3: train script with --probe mode to measure tok/s on the
  user's laptop before the real run and print wall-clock estimate.
